# Apple 대한민국 홈페이지 UI/UX 분석 보고서

**대상:** [apple.com/kr](https://www.apple.com/kr/) 홈페이지
**관찰일:** 2026년 9월 28일(한국 시간)
**방법:** Windows의 Chromium 브라우저에서 실제 화면, 접근성 스냅샷, DOM, 계산된 CSS, 주요 상호작용을 확인했다. 뷰포트는 390×844, 768×900, 1024×900, 1440×900px과 전환점 인접 너비를 사용했다. 제품·프로모션 내용은 수시로 바뀌므로 아래 내용은 관찰 시점의 스냅샷이다.

> **해석 범위:** 화면·DOM·CSS에서 직접 확인한 사실과 그로부터의 UX 해석을 구분했다. 서버의 내부 아키텍처, 실제 사용자 전환율, 모든 브라우저의 접근성 준수 여부는 이 조사만으로 확인할 수 없다. 화면에 삽입된 제삼자 `unicorn-web-assistant` 요소는 Apple 사이트의 구성 요소가 아니므로 증거 캡처에서 제거했다.

## 1. 핵심 요약

이 홈페이지는 **전역 카테고리 탐색 → 현재 캠페인 혜택 → 신제품 대형 전시 → 보조 제품·서비스 전시 → Apple TV 갤러리 → 법적 정보와 디렉터리** 순서로 설계돼 있다. 사용자는 첫 화면에서 제품 이름과 하나의 짧은 메시지를 본 뒤 `더 알아보기` 또는 `구입하기/가격 보기`로 갈라진다. 상단 탐색은 제품군을 찾는 경로, 각 타일의 CTA는 이미 관심이 생긴 제품으로 이동하는 경로다.

시각 표현은 넓은 여백, 중앙 정렬 제목, 큰 제품 이미지, 제한된 문구, 검정/밝은 회색의 교대 배경과 파란 CTA에 집중한다. 데스크톱에서는 대형 전폭 타일 3개와 2열 프로모션 6개를 보여 주고, 모바일에서는 모든 타일을 한 열로 바꾸며 전역 탐색을 전체 화면 단계형 메뉴로 전환한다.

상단의 혜택 문장은 구매 의도를 방해하지 않을 만큼 짧고, 제품 타일은 **제품명 → 한 줄 약속 → 두 개의 행동**이라는 반복 패턴을 따른다. 반복 덕분에 사용자는 새 타일에 도달할 때마다 조작 방식을 다시 배울 필요가 없다. iPhone Duo처럼 아직 출시 전인 제품은 `구입하기` 대신 `가격 보기`를 사용하고 사전 주문·출시일을 제목 아래에 노출한다. 이는 콘텐츠 상태에 따라 CTA 문구를 바꾸는 사례다.

## 3. 탐색 UX

### 데스크톱 전역 메뉴

1440px 화면의 헤더는 높이 **44px**, 밝은 반투명 배경(`rgba(245,245,247,.8)`)이며 스크롤 중에도 상단에 남는 `position: fixed`다. 제품군 링크에 포인터를 올리면 페이지 위에 넓은 플라이아웃이 열리고 아래 콘텐츠가 어두워지며 흐려진다. 실제로 Mac을 호버했을 때 메뉴 버튼의 `aria-expanded`가 `true`로 바뀌고 해당 하위 메뉴가 표시됐다.

플라이아웃은 제품 모델 목록을 가장 큰 글씨로 배치하고, 옆 열에 **쇼핑 경로**와 **관련 항목·지원**을 작은 글씨로 배치한다. 모델 탐색과 구매 지원을 한 번에 제공하면서도 시각적 우선순위는 제품에 둔다. 메뉴는 헤더 전체 아래에 붙어 있어 사용자가 다른 제품군으로 포인터를 이동하며 탐색할 수 있다.

![Mac 플라이아웃](playwright/apple-desktop-menu.png)

### 모바일 전역 메뉴

390px 화면의 헤더는 높이 **48px**이며 Apple 로고, 검색, 쇼핑백, 메뉴 아이콘만 남는다. 메뉴를 누르면 기존 화면 대신 전체 화면 목록이 열린다. 처음에는 제품군 이름을 약 **큰 제목 크기**로 넉넉하게 세로 배열하고, Mac을 누르면 `Mac 모두 살펴보기`, 개별 모델, 비교·전환, 쇼핑·지원 링크가 나타나는 하위 단계로 이동한다. 하위 단계에는 뒤로 가기와 닫기가 따로 있다. 메뉴가 열릴 때 접근성 트리에는 `dialog "Menu"`가 생기고 본문은 `aria-hidden`으로 처리됐다.

이 구조는 좁은 화면에서 수평 메뉴를 무리하게 압축하지 않고 **한 번에 하나의 탐색 단계**만 보여 준다. 단점은 특정 지원 링크에 도달할 때 메뉴 열기와 하위 메뉴 진입이 추가된다는 점이다.

![모바일 첫 화면](playwright/apple-mobile-home.png)
![모바일 전체 화면 메뉴](playwright/apple-mobile-menu.png)

### 검색·쇼핑

검색 아이콘을 누르면 현재 페이지를 떠나지 않고 검색 입력창과 다섯 개의 빠른 링크가 나타난다. 입력창은 바로 포커스를 받으며 접근성 트리에서 `search` 영역과 `textbox "apple.com 검색하기"`로 드러난다. 뒤쪽 페이지는 어둡고 흐린 배경으로 처리돼 현재 조작 대상에 주의를 모은다. 쇼핑백은 같은 상단의 별도 진입점으로 항상 남는다.

## 4. 시각 디자인 시스템

| 요소 | 데스크톱 1440px 관찰값 | 모바일 390px 관찰값 | 역할 |
|---|---:|---:|---|
| 전역 헤더 | 높이 44px | 높이 48px | 탐색의 고정된 기준점 |
| 혜택 리본 | 높이 54px | 높이 76px | 짧은 상업 메시지; 좁은 폭에서 2행 |
| 대형 히어로 타일 | 높이 692px | 높이 500px | 캠페인의 최대 시각 비중 |
| 대형 제목 | 56px, 굵기 600, 행간 약 66px | 32px, 굵기 600, 행간 약 38px | 제품 식별 |
| 히어로 부제 | 28px, 행간 35px | 19px, 행간 25px | 한 문장의 가치 제안 |
| 기본 CTA | 17px, 높이 44px | 14px, 높이 36px | 가장 명확한 다음 행동 |
| 프로모션 타일 | 높이 580px, 2열 | 높이 500px, 1열 | 보조 제품 전시 |
| 프로모션 제목 | 40px | 32px | 히어로보다 한 단계 낮은 위계 |

서체는 로드된 CSS에서 `SF Pro KR`을 한국어의 첫 후보로 사용하며 제목에는 `SF Pro Display`, 일반 UI에는 `SF Pro Text` 계열을 조합한다. 첫 히어로의 배경은 검정, 제목은 `rgb(245,245,247)`이다. 기본 CTA는 `rgb(0,113,227)`의 채운 파란색, 보조 CTA는 투명 배경에 파란 외곽선이다. 버튼의 계산된 `border-radius: 980px`는 완전한 알약 형태를 만든다. 같은 CTA 대비 구조가 여러 타일에서 반복된다.

각 히어로의 위쪽에는 제목·부제·버튼을 중앙 정렬하고, 아래쪽에 큰 기기 이미지를 놓는다. 이 배열은 먼저 **제품과 의미를 읽고**, 다음에 물체의 형태를 확인하도록 시선을 이끈다. 이미지가 짙거나 밝은 배경에 따라 `theme-dark` 같은 타일 클래스가 붙고 글자·버튼 대비가 맞춰진다. 일부 Watch·iPad 타이틀은 글자 로고 이미지를 사용하며, 접근성 트리에는 제품명 텍스트가 별도로 제공됐다.

## 5. 반응형 설계: 실제 전환점

| 경계 | 1px 아래/위의 관찰 | 결과 |
|---|---|---|
| **734 → 735px** | 734px에서 히어로·프로모션 모두 500px 높이의 1열; 735px에서 히어로 650px, 프로모션 2열·490px | 콘텐츠 타일의 모바일/중간 화면 전환 |
| **833 → 834px** | 헤더 48px → 44px | 모바일 전체 화면 메뉴에서 데스크톱 전역 탐색으로 전환 |
| **1068 → 1069px** | 히어로 650px → 692px, 프로모션 490px → 580px, 제목 48px → 56px | 대형 화면용 비례·이미지 규모 전환 |

이 전환점은 동일하지 않다. **콘텐츠 그리드는 735px부터 2열이지만 헤더는 833px까지 모바일 메뉴**를 유지한다. 즉 콘텐츠에 필요한 너비와 11개 내비게이션 항목에 필요한 너비를 별도로 판단한 설계다. 768px에서 프로모션은 2열이고 헤더는 모바일 메뉴였으며, 1024px에서는 2열과 데스크톱 헤더가 함께 표시됐다. 본문에 가로 넘침은 이 표본 너비에서 관찰되지 않았다.

반응형 이미지는 단순 축소가 아니다. 첫 히어로의 `<picture>`에는 `max-width:734px`, `max-width:1068px` 등 조건별 `<source srcset>`가 있고 1×/2× 자산을 제공한다. 모바일 캡처에서는 데스크톱의 가로 기기 연출 대신 좁은 화면에 맞는 세로 구도로 표현됐다. 이렇게 텍스트와 이미지의 **구도 자체**를 기기 폭에 맞춰 바꾼다.

## 6. 엔터테인먼트 갤러리

하단 Apple TV 갤러리는 가운데 카드를 크게 보여 주고 양옆 카드 일부를 노출한다. 사용자는 다음 콘텐츠가 있음을 즉시 알 수 있다. 각 카드에는 이미지 위에 `지금 시청하기` CTA와 장르·짧은 설명이 놓인다. 아래에는 여섯 개의 페이지 표시와 재생 제어가 있다. 예를 들어 5번 표시를 클릭하면 `aria-selected="true"`가 5번 탭으로 옮겨가고 해당 카드가 `current-item`으로 바뀌었다.

접근성 구조는 `role="group"`의 갤러리, `tablist`, 각각 이름이 있는 `tab`, 대응하는 `tabpanel`, `Apple TV 갤러리 재생` 버튼으로 구성된다. 관찰 시 제어는 재생 상태였고, `prefers-reduced-motion: reduce`를 설정한 상태에서도 갤러리는 일시 정지 상태로 표시됐다. 이것만으로 모든 동작 감소 처리를 검증했다고 볼 수는 없다.

## 7. 공개된 프런트엔드 구현 단서

1. **의미 구조:** 문서는 `lang="ko-KR"`, 화면 읽기용 `h1 "Apple (대한민국)"`, `main`, 전역 `nav`, `footer`를 가진다. 대형 제품은 `h2`, 프로모션은 `h3`로 계층을 나눈다. 이미지 31개 모두 `alt` 속성이 있었고, 그중 22개는 장식용 빈 `alt`였다. 주요 제품 이미지는 설명형 대체 텍스트가 접근성 트리에 나타났다.
2. **타일 구성:** 각 타일은 절대 배치된 전체 타일 링크(`tile-link`), 상대 배치된 텍스트·CTA(`tile-content`), 이미지 래퍼(`tile-image-wrapper`)로 이루어진다. 전체 영역 링크는 `aria-hidden="true"`와 `tabindex="-1"`로 접근성 트리·키보드 순서에서 제외하고, 명시적인 CTA 링크에는 `더 알아보기, iPhone 18 Pro`처럼 제품명을 포함한 이름을 준다. 따라서 포인터용 넓은 클릭 영역과 키보드·화면 읽기용 구체적인 링크를 함께 제공한다.
3. **스타일·동작 분리:** 전역 헤더, 전역 푸터, 로컬 내비게이션, 홈페이지 본문, 갤러리, 인라인 미디어가 각각 별도 CSS/JS 자산으로 로드됐다. 관찰된 경로에는 `globalheader.css`, `ac-globalfooter.built.css`, `main.built.css`, `homepage.built.css`, `home-gallery.built.css` 및 대응 스크립트가 포함된다. 이는 공개 자산 기준의 구성이고 내부 소스 저장소의 모듈 구조를 뜻하지는 않는다.
4. **지역화·검색 메타데이터:** `<title>`은 `Apple (대한민국)`, `canonical`은 `https://www.apple.com/kr/`, 뷰포트는 `width=device-width, initial-scale=1, viewport-fit=cover`다. `hreflang` 대체 링크 137개가 관찰됐다. 한국어 웹 폰트와 한국어 전용 홈페이지 스타일도 별도로 로드된다.
5. **측정·콘텐츠 제어:** 섹션과 갤러리 요소에 `data-analytics-region`, `data-analytics-section-engagement`, `data-analytics-gallery-id` 같은 속성이 있다. 이는 어떤 UI가 분석 계측 대상으로 준비됐는지 보여 주지만 실제 분석 결과를 말해 주지는 않는다.
6. **테마 정책:** 운영체제 다크 모드를 흉내 냈을 때도 본문 배경은 흰색이고 히어로의 검정 배경은 유지됐다. 페이지는 시스템 전체의 다크 테마 전환보다 캠페인 타일별 명암을 우선한다.

### 로딩·성능 관점

홈페이지에는 관찰 시점에 `<picture>` 요소 31개가 있었고, 제품에 따라 화면 폭·픽셀 밀도별 이미지를 선택하도록 `source`와 `srcset`가 구성됐다. 이는 고해상도 화면의 선명도와 모바일 구도를 함께 제어하는 방식이다. 이미지와 갤러리 자산이 크기 때문에 실제 체감 성능은 회선·캐시·기기 성능의 영향을 받는다. 이번 조사는 제어된 저속 네트워크·CPU 조건의 성능 실험이 아니므로 LCP, CLS, INP 점수나 전송량을 사이트 전체의 품질 지표로 제시하지 않는다. 구현을 재현한다면 첫 히어로 표시 시점, 이미지 형식·용량, 화면 아래 자산의 로딩 시점, 갤러리 동작 중 메인 스레드 비용을 별도 측정해야 한다.

## 8. 접근성·사용성 평가

**잘 작동한 점**

- 모바일 메뉴가 열린 동안 본문을 접근성 트리에서 숨기고, 메뉴를 `dialog`로 노출한다.
- 검색 입력에 즉시 포커스를 주고, 갤러리 탭은 이름과 선택 상태를 제공한다.
- 모바일 푸터 디렉터리는 `aria-expanded`가 있는 버튼형 아코디언이다. `쇼핑 및 알아보기`를 누르면 상태가 `false`에서 `true`로 바뀌고 목록 링크가 드러났다.
- 확인한 색상 표본의 대비는 흰 글자/기본 파란 CTA 약 **4.70:1**, 짙은 배경/밝은 제목 약 **15.46:1**이다. 이는 특정 표본의 계산값일 뿐 페이지 전체의 WCAG 판정은 아니다.

**주의할 점**

- 조사한 DOM에서 본문으로 바로 가는 스킵 링크를 찾지 못했다. 헤더의 항목이 많으므로 키보드·화면 읽기 사용자에게 탐색 비용이 커질 수 있다.
- 본문은 시각적으로 간결하지만 페이지 끝에는 긴 혜택·제품 각주와 촘촘한 12px 푸터 텍스트가 있다. 세부 조건을 확인하는 작업은 별도 읽기 부담이 생긴다.
- 모바일 전체 화면 메뉴의 깊은 링크는 추가 단계와 긴 스크롤을 요구한다. 모델 링크를 크게 배치한 장점과 탐색 길이 사이의 절충이다.
- 이 조사는 Chromium의 제한된 화면·상태에서 이루어졌으며 실제 VoiceOver 사용, 터치 기기, 저속 네트워크, 고배율 확대, 전체 키보드 순환을 포괄하지 않는다.

## 9. 다른 사이트에 적용할 수 있는 설계 원리

1. 첫 화면의 설명을 늘리기 전에 **제품명·핵심 약속·다음 행동**을 일관된 순서로 배치한다.
2. 콘텐츠 그리드와 헤더는 같은 전환점을 강요하지 말고 각각 필요한 공간으로 판단한다.
3. 모바일 이미지는 데스크톱 이미지를 줄이기만 하기보다, 좁은 폭에서 주요 피사체가 살아나는 구도를 별도 제작한다.
4. 상세 탐색 링크와 구매 링크를 분리하고, 출시 상태에 맞춰 CTA 문구를 바꾼다.
5. 갤러리와 메뉴에 시각적 변화뿐 아니라 `aria-expanded`, `aria-selected`, 이름 있는 버튼과 패널을 함께 제공한다.
