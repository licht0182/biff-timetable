# 내 시간표 날짜 선택 레이아웃 통일

작성일: 2026-10-03 (KST)

## 요청과 재현

시간표의 날짜 선택 버튼은 일반 테두리와 한 줄 날짜를 사용했고, 목록은 날짜·요일·일정 개수를 세 줄로 표시했다. WebKit 393px 재현에서 목록 버튼 높이는 68.25px, 시간표 버튼 높이는 44px였고 시간표에는 글래스 마스크 테두리가 없었다.

## 변경

- 시간표 날짜 버튼에 기존 `ui-text-chip` 리퀴드 글래스 테두리를 적용했다. 테두리는 기존 액션 버튼과 같은 마스크·그라디언트 방식이다.
- 목록과 시간표에서 `timetable-day-button` 스타일과 `10월 10일 토` 형식을 공유한다.
- 두 날짜 선택 영역의 간격·안쪽 여백·높이·글꼴·선택 색상을 통일했다. 버튼 높이는 44px이며 날짜가 많으면 한 줄로 가로 스크롤한다.
- 목록의 일정 개수는 날짜 아래 목록 제목의 ‘N개 일정’에 표시한다.
- 기존 목록 탭의 접근성 연결, 시간표의 방향키·Home/End 이동, 버튼의 색상 피드백을 유지한다.
- 기존 목록 전용 다단 버튼 스타일을 정리했다. 카드 모양 및 앞서 수정한 중복 테두리 처리도 유지한다.

## 검증

- TypeScript 검사와 Vite 빌드 성공.
- 수정 후 날짜 선택·목록 검사 **30개 통과**: Chrome 날짜 5개, WebKit 날짜 5개, 두 엔진 목록 20개. 실패·flaky·제외 0.
- 동일 UI 코드의 기존 시간표 날짜 이동 38개와 버튼 10개도 통과했다. 관련 고유 검사 합계는 **78개**이며, 전체를 한 번에 재실행한 집계는 아니다.
- 초기 검사에서 Chrome의 마스크 직렬화 표현(`exclude, exclude`)과 이전 목록 선택 색상을 전제로 한 기준을 조정했다. 수정한 검사는 선택·비선택 색상의 구분과 실제 마스크 동작을 확인한다.
- WebKit 검사 실행 목록에 새 날짜 선택 파일을 추가해 CI에서도 두 엔진이 실행한다.
- 실제 Chrome/WebKit × 320·393·768·1440px에서 목록·시간표 버튼의 문구·크기·글꼴·배경·글자 색이 일치했다. 전부 한 줄, 투명한 일반 테두리와 글래스 마스크, 44px 높이, 페이지 가로 넘침 0px을 확인했다.
- 393px 다크 모드의 두 화면도 직접 확인했다. WebKit 캡처는 모드 변경 뒤 두 렌더 프레임을 기다려 실제 표시된 화면을 기록했다.
- 사용자 지침에 따라 PWA는 별도로 검사하지 않았다.
- 독립 읽기 전용 검토 결과 `ship`. 검증 식별자, CSS 우선순위, 접근성 연결, 저장된 검사 결과 및 확정 캡처를 확인했다.
