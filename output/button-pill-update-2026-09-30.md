# 버튼 및 시간표 메뉴 개편

## 적용한 요청

- 일반 버튼은 알약형이며 글씨와 아이콘 묶음이 상하좌우 중앙에 위치한다.
- 사용자 최종 수정에 따라 도슨트 카드, 시간표 일정 블록, 시간표 목록의 클릭 영역, 전체 검색의 빠른 링크 타일은 기존 카드 모양과 정렬을 유지한다.
- 목록/시간표는 하나의 알약형 그룹에 묶인 두 버튼으로 전환한다. 선택 상태를 색상과 `aria-pressed`로 표시하고 기존 저장된 보기 방식도 유지한다.
- 모바일 시간표 메뉴는 빈 상태, 일정이 있는 상태, 삭제 선택 상태 모두 한 줄로 배치한다. PNG 저장은 더보기에서 실행하며 삭제 선택 중 일정 추가도 더보기에서 실행한다.
- 버튼의 확대·축소·떠오름·반동 효과를 제거했다. 눌림은 120ms 배경색·글자색·테두리색 변화로 표시한다. 하단 탭 선택 표시도 누를 때 크기가 변하지 않으며 탭 변경 시 즉시 새 위치를 표시한다.
- 도슨트 카드의 기본 그림자는 유지하고 마우스를 올릴 때 그림자가 강조되는 효과는 제거했다.

## 구현

- `src/button-pill.css`: 카드 예외를 포함한 일반 버튼 모양·정렬과 색상 반응. 표시 방식에는 `:where()`를 사용해 기존 반응형 숨김 규칙의 우선순위를 보존한다.
- `src/components/TimetableViewSwitch.tsx`: 목록/시간표의 공통 전환 그룹.
- `src/timetable-more-menu.css`, `src/App.tsx`: 12px 글씨, 전환 버튼의 44px 높이, 한 줄 메뉴, 모바일 추가 메뉴.
- `src/components/LiquidTabBar.tsx`: 선택 표시의 스프링 이동 및 누를 때 변형하는 로직 제거. 실제 버튼 좌표 측정과 키보드·포인터 클릭 연결 유지.
- `src/main.tsx`: 공통 버튼 CSS를 마지막에 적용.

## 검증

- 데이터 검사 4종과 TypeScript/Vite 빌드 통과.
- 최종 집중 검사: Chromium·WebKit에서 버튼/시간표/하단 탭 54개 통과.
- 도크 위치·크기 검사 3종을 브라우저별 3회 반복한 18개 검사 통과.
- 더보기 메뉴를 통한 모바일 PNG 저장과 데스크톱 직접 저장을 포함한 실제 PNG 생성 검사는 Chromium 5개와 별도 WebKit 프로젝트 5개가 통과했다. iPhone 사용자 에이전트의 이미지 저장 미리보기도 포함하며, 기존 PNG 검사도 새 메뉴 경로를 사용하도록 수정했다.
- 실제 CLI 브라우저: 320·390(다크)·402·768·1440px의 네 탭, 총 20개 화면에서 일반 버튼 모양·정렬 문제 0건, 페이지 가로 넘침 0px.
- 768·1440px에서 모바일 전용 필터 버튼 두 개의 `display:none` 확인.
- 기존 카드의 사각형 모양과 왼쪽 정렬 및 클릭 동작을 확인했다. 누르는 동안 일반 버튼의 위치·크기가 고정되고 색상 반응만 나타나는 검사도 통과했다.
- 전체 회귀에서 아이콘 버튼의 이전 모서리 기대값과 화면 갱신 중 분리된 DOM 노드를 읽는 검사 문제를 수정했다. WebKit 예매 대안 적용 실패는 밝기 필터를 제거하면 통과하는 것을 확인해, 눌림 반응을 필터 대신 색상 속성으로 구현했다.
- 첫 독립 검토의 CSS 숨김 충돌을 실제 브라우저에서 재현한 뒤 수정했다. 수정 후 새 독립 검토에서 배포 가능한 판정을 받았다.
- 그림자 강조 제거와 실제 카드 hover 검사까지 포함한 최종 전체 회귀: **343개 통과, 기존 건너뛰기 1개, 실패 0개, 재시도 성공 0개**. 실행 시간은 약 7분 32초이며, 별도 버튼·카드 집중 검사 10개도 통과했다.
- 사용자의 검사 기준에 따라 별도 PWA 검사는 수행하지 않는다. 일반 사이트 통과를 PWA 통과로 간주한다.

## 최종 결과

최종 코드의 전체 회귀와 새 독립 검토가 모두 통과했다. 커밋 후 GitHub Pages 배포 및 공개 사이트 반영을 확인한다. 배포 커밋과 워크플로 결과는 별도의 배포 확인서에 기록한다.
