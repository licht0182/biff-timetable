# BIFF Timetable 화면 크기별 UI 수정 및 검증

## 요구사항

- 직접 촬영한 화면을 기준으로 과도한 버튼 크기, 글자 비율, 좌우·상하 정렬과 가로 넘침을 확인한다.
- 모든 탭의 상단 제목·설명·검색·선택 수·내비게이션 배치를 영화 찾기와 통일하고, 상단 테두리를 글래스모피즘에 맞춘다.
- 카드 모양과 내용 정렬은 유지한다. 일반 버튼은 알약형이며 누를 때 색상만 바뀐다.
- 모바일 시간표 메뉴는 한 줄, 목록/시간표 전환은 묶인 알약형 컨트롤을 유지한다.
- 일반 사이트 검증 결과를 PWA 결과로 간주하며 별도 PWA 점검은 하지 않는다.

## 직접 관찰한 문제와 수정

| 화면/상태 | 관찰 및 원인 | 수정 |
| --- | --- | --- |
| 320px 시간표 메뉴 | 선택 버튼 약 34×50px, 더보기 약 45×50px로 세로 타원 형태. 짧은 글자 대비 높이가 큼 | 액션 44px, 묶음 내부 버튼 38px, 일반 액션 최소 폭 44px |
| 390·700px 시간표 메뉴 | 더보기의 `margin-left:auto` 때문에 다른 버튼들과 과도한 간격 | 모바일에서는 일정한 간격으로 한 줄 배치 |
| 영화 목록 | 관심 버튼은 36px, 상세 버튼은 공통 칩의 `3.6em` 최소 높이에 의해 별도 크기 | 일반 칩 40px, 모바일 44px 기준. 관심 버튼도 같은 기준 적용 |
| 상세 필터 창 | 완료 버튼이 폭 44px/높이 약 50px로 길어짐 | 완료 버튼 44×44px 및 중앙 정렬 |
| 예매 확인 창 | 공통 높이 변경 후 적용 버튼이 40px로 낮아지는 회귀 | 대화상자 칩은 44px 최소 높이 유지 |
| 겹치는 일정 11개 | 하루 보기에서도 데스크톱 약 90px, 모바일에는 그보다 훨씬 좁은 칸으로 제목 압축 | 실제 겹침 수로 캔버스 폭 계산. 카드 폭 112px 확보, 시간표 내부에서만 가로 이동 |
| 밀집 시간표 가로 이동 | 넓어진 캔버스 중앙의 날짜명이 화면 밖으로 나갈 수 있음 | 실제 스크롤 컨테이너 폭을 기준으로 날짜 헤더와 시간축 고정 |
| 시간표 상단 | 모바일에서 부제가 사라지고 제목이 9~16px 아래로 이동. 테두리도 1px 차이 | 모든 탭의 제목·부제·로고·선택 수·검색 배치를 영화 찾기와 통일. 실제 상단 높이와 제목 위치 차이 0px |
| 상단 테두리 | 새 물리 테두리와 추가 하이라이트가 기존 유리 가장자리와 겹쳐 1px 기하 차이 발생 | 물리 테두리와 추가 효과 제거. 기존 React 유리 레이어의 1px 가장자리 하나로 통일하고 기존 테마·투명도 감소 정책 유지 |
| 390px 상단 부제 | 마지막 ‘요.’만 둘째 줄로 내려감 | 글자 크기를 유지하면서 두 줄을 균형 있게 배치 |
| 모바일 상세 창 관심작 버튼 | 아이콘 전용 고정 폭이 텍스트 버튼에도 적용되어 글자가 세로로 줄바꿈 | 영화 카드의 아이콘 버튼으로 고정 폭 적용 범위 제한 |
| 일정 창 닫기 | 버튼이 30×30px로 주변 조작보다 작음 | 영화 상세·일정 창 닫기 모두 44×44px |

## 캡처 범위 및 측정

- Chromium 직접 캡처: 320, 390, 700, 701, 767, 768, 1024, 1440, 1920px.
- 영화 찾기, 시간표, AI 도슨트, 설정과 일정이 많은 시간표를 확인했다.
- 최종 Chromium 캡처 45개 상태에서 페이지 가로 넘침은 모두 0px.
- WebKit 직접 캡처: 320, 390, 768, 1440px의 20개 상태. 페이지 가로 넘침 0px.
- 두 엔진의 모든 검사 폭에서 탭별 상단 높이 차이 0px, 제목 위치 차이 0px, 부제 표시 일치.
- 상단 물리 테두리 폭은 0px, 실제 유리 가장자리 레이어는 탭마다 정확히 하나다. 기존 검정/흰색 유리 하이라이트 구조를 유지한다.
- 실제 상영 12개를 넣은 밀집 날짜는 11개 동시 칸. 최소 카드 폭 112px, 페이지 넘침 0px.
- 밀집 시간표 내부 넘침: 320px 화면 1014px, 390px 화면 944px, 1440px 화면 194px. 내부 스크롤이 의도적으로 발생하며 페이지 전체는 넘치지 않는다.
- 일정 카드의 각진 형태·왼쪽 텍스트 정렬·시간 좌표를 유지했다.

## 검증 상태

- 데이터 검증 4종과 TypeScript/Vite 빌드 통과.
- 최초 개발 서버 회귀 실행: 342 통과, 5 실패, 1 제외. 예매 버튼 높이 2건은 수정했으며, 요청 중복/청크 검사 3건은 개발 서버와 배포 빌드의 차이를 확인하여 정적 preview로 재검증한다.
- 상단 통일 전 전체 회귀: 353 통과, 1 제외, 실패·재시도 없음.
- 상단 통일 첫 빌드: 363 통과, 8 실패, 1 제외. 실패 8건은 모두 모바일 헤더의 1px 높이 차이를 잡은 새 검사였다. 해당 CSS를 수정했다.
- 높이·테두리 수정 후 상단/밀집 일정/예매 버튼 집중 검사 26개 통과, 실패·재시도 없음.
- 이후 전체 회귀에서 367 통과, 4 실패, 1 제외. 4건은 두 엔진의 유리 가장자리 기하 검사로, 중복 하이라이트와 물리 테두리를 제거해 수정했다.
- 유리 가장자리·상단·밀집 일정·상세 창 보정 집중 검사 38개 통과, 실패·재시도 없음.
- 실제 버튼 누름 확인: Chromium/WebKit 모두 위치·크기 변화 0px, `transform:none`, `animation-name:none`. 배경색만 반투명 흰색에서 강조색으로 바뀐다.
- 마지막 실측에서 모바일 관심 아이콘의 높이 40px 잔여 규칙을 발견하여 폭·높이 모두 44px로 보정하고 회귀 검사에 추가했다.
- 유리·상세 창 보정 후 전체 회귀: 375 통과, 1 제외, 실패·재시도 없음.
- 마지막 관심 아이콘 보정 후 버튼·상세 창 집중 검사: 16 통과, 실패·재시도 없음. Chromium/WebKit 새 브라우저에서도 모바일 44×44px, 데스크톱 40×40px 및 색상만 바뀌는 누름 반응을 확인했다.
- 최종 소스 전체 회귀: 375 통과, 1 제외, 실패·재시도 없음 (`responsive-ready-2026-10-03.json`).
- 새 독립 검토: SHIP. 검토 후 소스 지문이 그대로임을 확인했다. 배포 결과는 별도 배포 확인 보고서에 기록한다.
